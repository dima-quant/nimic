The nimic code in nraytracer transpiles to properly working Nim but when executed directly in Python it still needs debugging to run and produce the same results. This should be mostly fixed by improving the nimic module. If the nimic code in nraytracer needs to be changed, the change should be minimal, the reason should be clearly formulated and user confirmation should be requested, after the change the code should be tested to compile to the proper Nim code and produce the same results. When improving the nimic module, if the fix is not directly obvious, the problem should be clearly formulated and possible solutions should be presented to the user for confirmation before implementing the fix. The goal is to make the nimic module sufficintly comprehencive such that the nimic code in nraytracer can be executed directly in Python without any modifications and produce the same results as the Nim code to which it transpiles. One feature of the Nim code is to be able to access attributes of pointer content without explicitly dereferencing the pointer, as well as with the explicit dereferencing (via .contents). This should be preserved as much as possible by the nimic module. The debug process can leverage the fact that the nimic code produces correct results when transpiled to Nim and intermediate results can be produced and inspected where needed. The debug process should be iterative, with each iteration producing a small improvement to the nimic module and producing a test case that demonstrates the improvement. The test cases should be added to the tests folder as they are developed. The std function names should be in lowercase and snake_case to match Python conventions. Because Nim syntax does not distinguish between method and function calls, when debugging nimic code some method calls should be written as function calls and vice versa.
